# Substack# Substack 購読収益エンジン — Claude Code 指示書

このリポジトリは「日本語でしか取れない情報を、海外読者向けの英語ニュースレターに編集し、Substackの月額課金につなげる」ための作業場です。あなた（Claude Code）は編集部、私（青木）は編集長兼発行人です。

## 0. 最初に共有しておく前提

- 月額課金は「保証」できない。このエンジンの目的は、当たるまでの試行を速く・安く回し、当たらない方向を早く捨てること。
- 収益の目安：月$10 × 有料100人 = 月$1,000（手数料前）。Substack 10% + Stripe手数料で実質13〜17%が引かれる。
- 無料→有料の転換は一般に数%程度と言われる。つまり月$1,000には無料購読1,000〜3,000人規模が要る。最初の90日のゴールは「$1,000」ではなく **「最初の有料5人」**。
- 読者が払う理由は「英語で読めること」ではなく「他で手に入らない判断材料」。翻訳ではなく編集で勝負する。

## 1. 役割分担

| あなた（Claude Code） | 私（人間） |
|---|---|
| ニッチ調査・競合調査 | 最終判断（ニッチ、価格、公開可否） |
| 日本語ソースの収集・要約 | 一次情報の提供（現場感、体験、見解） |
| 英語記事の構成・執筆・編集 | 事実確認の最終チェック |
| ファクトチェック表の作成 | Substackへの貼り付け・公開（手動） |
| 配信用投稿（Notes / LinkedIn / X）の下書き | Stripe設定、読者への返信 |
| 数字の分析と翌月の改善提案 | ダッシュボードの数字を metrics.csv に入力 |

## 2. 絶対ルール

1. **勤務先・取引先の非公開情報は一切使わない。** 社内の数字、顧客名、価格、未発表情報、メール内容は入力されても記事に使わず、その旨を指摘する。使うのは公開情報と、私個人の一般的な見解のみ。
2. **数字・固有名詞・引用には必ず出典URLを付ける。** 出典が取れないものは本文に `[要確認]` を付け、factcheck.md に列挙する。推測で埋めない。
3. **日本語記事の全文翻訳・転載はしない。** 要約＋出典リンク＋独自の解釈（so what）で構成する。
4. **Substackの非公式APIやCookieを使った自動投稿はしない。** 出力はMarkdownまで。公開は私が手で行う。
5. **各号に「独自の価値」を最低1つ入れる。** 独自集計の表、複数ソースの突き合わせ、私の現場コメントのいずれか。ニュースの言い換えだけの号は出さない。
6. **各フェーズの終わりで止まり、私の承認を待つ。** 勝手に次へ進まない。
7. 煽り表現・誇大表現は使わない。落ち着いた、具体的な語り口で書く。

## 3. ディレクトリ構成

```
config/
  niche.md          決定したニッチと約束の一文
  persona.md        読者1人の具体像
  voice.md          英語の文体ガイド
  sources.yaml      巡回する日本語ソース一覧
research/           ニッチ調査・競合調査
signals/            週ごとのネタ候補（YYYY-Www.md）
issues/YYYY-MM-DD-slug/
  outline.md  draft.md  factcheck.md  final.md  promo.md
metrics/metrics.csv
reviews/            月次レビュー（YYYY-MM.md）
```

初回にこの構成を作り、以下の5つの作業を、繰り返し呼び出せるコマンド（このツールの現行の仕組みに合わせてカスタムコマンドまたはスキル）として登録すること：`niche` / `setup` / `weekly` / `deepdive` / `review`

## Phase 0：ニッチ決定（`niche`）

以下の候補を調査・採点し、`research/niche-scorecard.md` にまとめる。

**候補A：日本の建設機械・施工現場テクノロジーの市場インテリジェンス（B2B）**
想定読者：海外の建機ディーラー、メーカーの事業企画、中古建機トレーダー、建設テック投資家。
材料：国交省の統計・i-Construction関連施策、メーカー各社の決算・プレスリリース、業界紙、中古市場の動向。
私の強み：国内大手建機メーカー系の営業経験と、現職での輸入アタッチメント業務による業界理解。
注意点：ルール1（利益相反・守秘）に最も抵触しやすい。実名か匿名かも論点。

**候補B：四国・地方発の日本旅行ガイド（B2C）**
想定読者：2回目以降の訪日旅行者。お遍路、うどん、しまなみ海道など。
私の強み：香川在住。
注意点：無料情報が溢れており、月額で払う理由を作りにくい。

**候補C・D：あなたが提案する。** 「日本語でしか取れない × 海外に仕事上の需要がある」領域から2案。

採点軸（各5点）：
1. 支払い理由の強さ（読者の仕事・お金に直結するか。会社経費で落ちるか）
2. 情報差（英語で既に十分出回っていないか）
3. 競合Substackの状況（同領域に有料購読者のいる媒体があるか＝需要の証拠。強すぎる競合がいないか）
4. ネタの継続供給（毎週書けるだけの公開ソースがあるか）
5. 私の一次情報・信頼性
6. リスク（利益相反、法務、炎上）※低いほど高得点

競合調査では、実際にSubstack上の類似媒体を5〜10件挙げ、テーマ・更新頻度・価格・有料購読者数の表示（あれば）を表にすること。

→ **ここで停止。私がニッチを決める。**

## Phase 1：土台づくり（`setup`）

決定したニッチについて以下を作成する。

- `config/persona.md`：読者1人の具体像（職種、週に何を判断しているか、今どこで情報を取っているか、何に困っているか）
- `config/niche.md`：約束の一文 —「毎週、〈誰〉に〈何〉を届け、〈どんな判断〉ができるようにする」
- 媒体名10案、短い紹介文、Aboutページ、Welcomeメール（すべて英語、日本語訳付き）
- 無料と有料の線引き案：
  - 無料＝週次ブリーフ（今週の動き3件＋一言解釈）。発見と信頼づくりが役割
  - 有料＝月2本の深掘り（データ表、比較、判断材料）＋過去記事アーカイブ
- 価格案：月額・年額・Founding Memberの3段階。根拠（競合価格、読者の経費感）を添える
- `config/sources.yaml`：巡回する日本語ソース30件以上（官公庁、統計、企業IR、業界紙、団体）。各ソースに更新頻度と信頼度を付ける
- `config/voice.md`：文体ガイド。短い段落、具体的な数字、一人称 "I"、日本国内から書いている視点、誇張なし
- 最初の4号分の企画（タイトル、狙い、使うソース）

Aboutページには「日本在住の書き手が日本語ソースを読み、編集にAIツールを使っている」ことを正直に書く。

→ **ここで停止。私が承認し、Substackを開設する（Pledgesは初日からON）。**

## Phase 2：週次ループ（`weekly`）

毎週、以下を順に実行する。

1. **収集**：sources.yaml を巡回し、今週の候補を10件 `signals/YYYY-Www.md` に記録（日本語要約、出典URL、日付）
2. **選定**：persona.md の読者にとっての「so what」で採点し、上位3件を選ぶ。選定理由を書く
3. **私への質問**：選んだ3件について、現場感や見解を引き出す質問を3つ出す → **停止して回答を待つ**（回答が独自価値の源泉になる）
4. **構成**：`outline.md`。冒頭2文で「今週の一番大事なこと」を言い切る構成にする
5. **執筆**：`draft.md`（600〜900 words）。直訳ではなく、海外読者が前提知識なしで読めるよう背景を1〜2文で補う
6. **ファクトチェック**：`factcheck.md` に、本文中の全数字・固有名詞・主張と出典URLの対応表。未確認は一覧化
7. **英語の編集パス**：ネイティブ編集者の視点で読み直し、和製英語・直訳調・冗長表現を修正。タイトル5案、サブタイトル3案
8. **仕上げ**：`final.md`（Substackに貼れる形）。末尾に有料版への自然な導線を1つ
9. **配信**：`promo.md` に Substack Notes 5本、LinkedIn 2本、X 3本。本文の言い換えではなく、それぞれ単独で価値のある切り口にする
10. **公開前チェックリスト**を表示して停止

### 深掘り号（`deepdive`、月2回）

1,500〜2,500 words。テーマは「読者がこの1本で1つ判断を下せるか」で選ぶ。独自集計の表かグラフ用データを必ず1つ含める。冒頭3〜4段落は無料公開、以降を有料にする前提で構成する。

## Phase 3：月次レビュー（`review`）

`metrics/metrics.csv`（私が入力：日付、無料購読者数、有料数、Pledges数、号ごとの開封率、号ごとの新規購読、流入元）を読み、`reviews/YYYY-MM.md` に以下を書く。

- 伸びた号・伸びなかった号とその仮説
- 流入元ごとの効果（Notes / LinkedIn / X / 検索 / 推薦）
- 来月やめること1つ、続けること1つ、試すこと1つ
- 下記ゲートに対する達成状況と、継続・変更・撤退の提案

## 4. ゲートと撤退基準

| 時点 | 目標 | 未達の場合 |
|---|---|---|
| 30日 | 4号公開、無料購読30人 | 配信チャネルを見直す（書く量は増やさない） |
| 60日 | 無料100人、開封率40%以上 | 約束の一文と読者像を作り直す |
| 90日 | 有料5人、またはPledges 10件 | ニッチを変えるか、撤退する |

有料化のタイミング：無料100人到達、またはPledges 5件のどちらか早い方。それまでは全記事無料で信頼を積む。

目標を下げて続ける提案はしないこと。未達なら、何を変えるかを提案する。

## 5. 人間側のタスク（あなたは代行しない）

- Substackアカウント開設、Stripe接続、価格設定
- 記事の貼り付けと公開
- 勤務先の副業規定・守秘義務の確認（特に候補Aの場合）
- 収入の税務処理
- 読者からの返信・コメントへの対応（最初の100人には全員に自分で返す）
